# P2-3 反向调用 Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新 example `host-caps` 演示 tool handler 反向调 sampling/roots，并用 canned 对端探针做 wire 验收。

**Architecture:** example 仿 `examples/apps-server/main.c` 骨架（stdio、SIGPIPE 忽略、
item_linked/content_linked 所有权模式）；对端探针是只回固定包的 stdio client；
脚本用 `mkfifo` 一对管道交叉连接两者 stdin/stdout。无 provider 时透传上游错误。

**Tech Stack:** C（mcpkit 公开 API）、sh、ctest。

---

### Task 2: host-caps example

**Files:**
- Create: `examples/host-caps/main.c`
- Modify: `examples/CMakeLists.txt`（加 target，仿 apps-server 两行）

- [ ] **Step 1: 写 main.c（抄 apps-server 骨架）**

`main`: `--help` 处理、`signal(SIGPIPE, SIG_IGN)`、`mcp_server_create(ctx,
"host-caps", "0.1.0")`、stdio transport serve。工具 `ask_model`（无参或
`{}` schema）：handler 内依次发 `sampling/createMessage`（取首个文本 content）
和 `roots/list`（取首个 root uri），拼 `text="model:<首段>; root:<uri>"`，
按 file-server 的 item_linked/content_linked 模式组装
`{"content":[{type,text}]}`。任一反向调用失败直接返回上游状态码，不伪造成功。

- [ ] **Step 2: 编译零警告**

Run: `cmake -S . -B build >/dev/null 2>&1 && cmake --build build --target host-caps 2>&1 | grep -ciE "warning|error:"`
Expected: `0`
