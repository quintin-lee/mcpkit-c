# MCP 2025-11-25 / 2026-07-28 支持设计（三期路线图）

**日期**：2026-11-09
**状态**：待评审
**范围**：让 mcpkit-c 真实支持 2024-11-05 ~ 2026-07-28 全部五个官方协议版本，每期交付后库可"完整声称"对应版本。

## 背景与现状

项目对 2025-11-25 / 2026-07-28 处于"半实现"状态：

- `include/mcpkit/protocol/initialize.h` 已定义 `MCP_PROTOCOL_VERSION_2025_11_25` /
  `MCP_PROTOCOL_VERSION_2026_07_28` 宏，但 `src/protocol/initialize.c` 的协商表
  `k_supported[]` 只有 `2025-06-18` 与 `2024-11-05`，且
  `MCP_PROTOCOL_VERSION_LATEST` 仍为 `2025-06-18`。
- `src/transport/streamable_http.c` 的 `is_supported_protocol_version` 已接受
  四个版本，且 `is_2026` 分支已实现 `Mcp-Method`/`Mcp-Name` 头校验、`_meta`
  版本匹配、无 session 请求路径（`sid==NULL && (_meta || server/discover)`
  时按请求创建临时 session）。
- 协议层已就位：`server/discover`（routes.c）、MRTR（`mrtr.c`/`mrtr_state.c`）、
  `subscriptions/listen`、tasks 扩展（`tasks.c`，含 `tasks/get`/`tasks/update`
  重设计）、skills 扩展（`skills.c`）。
- `src/protocol/sampling.c` 已实现 `tools`/`toolChoice`（SEP-1577），但未做版本门控。
- 错误码 `-32020`（HeaderMismatch）、`-32021`（MissingRequiredClientCapability）、
  `-32022`（UnsupportedProtocolVersion）已在 `message.h` 定义。

缺口分三层：**P1 版本对齐基线**（协商表 + 特性门控）、**P2 2026 核心无状态**
（resultType / CacheableResult / 门控补全）、**P3 授权强化**（RFC 9207 / 9728 /
CIMD / SEP-835）。

## 统一版本策略层（P1+P2 共享地基）

新增 `include/mcpkit/protocol/version.h`：

```c
typedef enum {
    MCP_PROTO_2024_11_05,
    MCP_PROTO_2025_03_26,
    MCP_PROTO_2025_06_18,
    MCP_PROTO_2025_11_25,
    MCP_PROTO_2026_07_28,
} mcp_proto_version_t;

const char *mcp_proto_version_string(mcp_proto_version_t v);
mcp_proto_version_t mcp_proto_version_parse(const char *s); /* 未知返回 0 */
bool mcp_proto_at_least(mcp_proto_version_t v, mcp_proto_version_t min);
```

`struct mcp_session`（`src/server/internals.h`，已含 `client_version`/
`client_meta` 字段）增加 `mcp_proto_version_t negotiated` 字段，作为
**所有路径的单一版本来源**：有状态路径由 `route_initialize` 在协商成功后
写入；2026 无状态路径由 `streamable_http.c` 在请求作用域 session 创建时
从 `_meta` 的 `io.modelcontextprotocol/protocolVersion` 写入。分发/路由
调用链（`mcp_server_dispatch` / `routes.c`）在需要版本门控处经
`mcp_session_negotiated(ctx, session)` 读取（新增只读访问器，session 为
NULL 时返回 `MCP_PROTO_2024_11_05` 作为保守基线），**不改 dispatch 签名**——
版本从 session 状态取，避免改动 11 个 `decorate_result` 调用点的参数面。
`async_server.c` 的 `session_entry_t` 不再单独存版本（消除双份状态；
它持有的 `mcp_session_t` 即唯一来源）。

| 行为 | ≤2025-11-25 | 2026-07-28 |
|---|---|---|
| 会话门禁 | `initialized` 前拒方法 | 无握手，请求自描述 |
| `Mcp-Session-Id` | 必传 | 禁用 |
| `ping`/`logging/setLevel`/`resources/subscribe` | 提供 | -32601 |
| `result.resultType` | 可选（缺省 complete） | 必填 |
| 日志级别 | `logging/setLevel` | `_meta.logLevel` 逐请求 |

`initialize.c` 改动：

- `k_supported[]` 扩展为 `2026-07-28`、`2025-11-25`、`2025-06-18`、
  `2025-03-26`、`2024-11-05` 五个版本。
- `MCP_PROTOCOL_VERSION_LATEST` 提升为 `2025-11-25`；`2026-07-28` 仅在客户端
  显式请求时激活（避免默认虚标 2026 授权强化等未交付特性）。
- **协商语义（显式定义）**：客户端请求 2026-07-28 走有状态 initialize 时，
  协商成功但 `route_initialize` 结果回显 `2025-11-25`（down-negotiation）；
  同时把 *请求的* 版本写入 `session->negotiated`（2026 语义按 2026 处理，
  回显版本仅为握手产物）。`route_server_discover` 的 protocolVersion 回显
  同规则改为取 `session->negotiated`（2026 请求回显 2026-07-28）。
- 新增 `mcp_initialize_result_new_v(ctx, negotiated, name, version)` 回显协商
  版本；旧 API `mcp_initialize_result_new` 保持（硬编码 LATEST，仅非 2026
  握手路径使用）。
- 2026-07-28 客户端不走 initialize（spec 已删握手）：经 `server/discover` +
  `_meta` 版本路由。
- 现有 `tests/unit/test_initialize.c` 的 2 版本协商矩阵需**扩展**为 5 版本
  （回归测试而非仅新增），保证 CI 绿。

P1 特性清单（门控 ≥2025-11-25）：

| 特性 | 实现点 |
|---|---|
| `icons` 元数据（tool/resource/template/prompt） | `registry.c` 注册 API 增加 icon URI 字段；不得为 data:/文件路径 |
| URL-mode elicitation（SEP-1036） | `client.c` elicitation 回调增加 `mode:"url"` 分支 |
| 扩展 ElicitResult（SEP-1330） | enum schema：titled/untitled、single/multi-select |
| sampling with tools（SEP-1577） | 已实现，仅版本门控 + 协商表声明 |

不纳入本期：`x-mcp-header`（SEP-2243，可作 P4 选项）、SEP-1699 SSE polling
（与 P2 删除 SSE resumability 冲突，跳过）。

## P2：2026-07-28 核心无状态（六块补全）

| # | 组件 | 位置 | 说明 |
|---|------|------|------|
| 1 | `resultType` 必填 + `input_required` 门控 | `routes.c` 结果构造按版本注入 | MRTR 中间结果已由 mrtr.c 覆盖 |
| 2 | `CacheableResult`（`ttlMs`/`cacheScope`）**版本门控** | **复用既有** `mcp_server_set_list_cache` API（server.h:435，已对 5 类结果生效）；P2 只做版本门控：2026 版本下若服务端未配置则结果注入缺省值（`ttlMs:0`，`cacheScope:"private"`）并记 WARN，≤2025 保持"未配置则省略" | 小（原 spec 误以为需新增 `mcp_cache_hint_t`，实际 API 已交付） |
| 3 | 错误码分区对齐 | 确认 -32020/-32021/-32022 数值与 spec 一致（message.h 已定义）；resource not found 错误码在 **2026 分支**改 -32602：**精确目标是 `route_resources_read` 的未知 URI 路径与 `route_tasks_get` 的 task-not-found 两处**（当前均返回 INVALID_PARAMS / NOT_FOUND 系），≤2025 路径不变 | 小 |
| 4 | `_meta` 逐请求能力读取 | 2026 下从 `_meta.clientCapabilities` 提取能力（替代 initialize）；`logLevel` 逐请求，未携带该字段的请求不得发 `notifications/message` | 中 |
| 5 | 废弃方法版本门控 | 2026 下 `ping`/`logging/setLevel`/`resources/subscribe`/`resources/unsubscribe`/`notifications/roots/list_changed`（请求形态）→ -32601；路由表加版本维度 | 小 |
| 6 | 确定性排序 | 2026 下 3 类 list 结果按 name 字典序（SHOULD） | 小 |

**Mcp-Session-Id 与 2026 冲突规则（显式定义）**：2026 请求若携带
`Mcp-Session-Id` 头，P2 下 **忽略该头并按无状态路径处理**（spec 2026 已删
会话概念，头无协议语义）；若该 sid 在旧路径有活跃 session 则不关联，
避免双份状态。

**共享代码风险（明确承认）**：`decorate_result`（routes.c 约 11 个调用点）
为所有版本共享。P2 的版本条件注入要求在该函数内读取
`mcp_session_negotiated` 并按版本分支——这是共享代码变更。因此修正验收
表述：~~"P2 不改动 ≤2025 行为路径"~~ → **"P2 不改变 ≤2025 响应的输出形态
（当服务端未配置 2026 专有字段时）"**；旧行为由现有测试矩阵（test_http_serve、
test_routes 等）守住。

数据流（2026 请求生命周期）：

```
POST /mcp (Mcp-Method + MCP-Protocol-Version: 2026-07-28 + _meta)
  → validate_http_metadata（头/版本/_meta 三方一致性，已实现）
  → 版本路由：parse(_meta.protocolVersion) == 2026 → stateless 分支
  → 临时 session（请求作用域，用完即弃）
  → dispatch：结果注入 resultType + cache hint + 确定性排序
  → MRTR：需用户输入时返回 input_required + inputRequests（不走流）
  → 请求结束 session 释放（跨调用状态走 tool 参数 handle）
```

P2 不改变 ≤2025 响应输出形态（旧客户端零回归，现有测试守住；共享的
`decorate_result` 按上表"共享代码风险"一节执行）。

## P3：授权强化（`src/core/auth.c` 已有 PKCE / RFC 8693 token exchange /
RFC 8414 AS metadata 基础；下表五项均为**净新增**）

| 项 | spec 来源 | 实现点 |
|---|---|---|
| RFC 9207 `iss` 校验 | 2026 授权强化 | 授权码兑换前校验 `iss` 与记录 issuer 一致；客户端必须验证存在时的 `iss` |
| CIMD 取代 DCR | SEP-991 | 新增 Client ID Metadata Documents 端点生成/解析；DCR 标记 deprecated（12 个月窗口） |
| Protected Resource Metadata 强制 | RFC 9728 | `.well-known/oauth-protected-resource` 端点 + `WWW-Authenticate` 可选头回退 |
| 增量 scope 同意 | SEP-835 | 401 响应 `WWW-Authenticate` 携带 `scope` + `resource_metadata` |
| OIDC Discovery 1.0 | 2025-11-25 | 授权服务器发现合并 OIDC 标准 discovery 文档 |

门控：≥2025-11-25 激活（9728/9207/CIMD 在 2026 下 MUST）；≤2025-06-18 保持现状。

## 测试策略（每 P 一个红灯门禁，TDD 先红后绿）

| P | 新增测试 | 关键断言 |
|---|---|---|
| P1 | `test_proto_negotiate.c` + **扩展** `test_initialize.c` 既有矩阵 | 5 版本协商矩阵；`result_new_v` 回显；2026 请求经有状态 initialize 时 down-negotiation 回显 2025-11-25；旧校验器对新版本仍通过 |
| P2 | `test_http_2026_stateless.c`（集成，加在 `tests/CMakeLists.txt` 的 `MCPKIT_BUILD_HTTP` 门控块内） | 2026 无 session 往返；`resultType` 缺失即失败；CacheableResult 门控（2026 未配置时注入缺省，≤2025 省略）；废弃方法（含 `notifications/roots/list_changed`）-32601；头不匹配 -32020；sid+2026 忽略头；`resources/read` 未知 URI 在 2026 下 -32602 |
| P3 | `test_auth_rfc9207_cimds.c`（单元） | `iss` 不匹配拒绝兑换；CIMD 文档往返；401 增量 scope 头格式 |
| 全量 | ASan + 零回归 | 2024/2025-03-26/2025-06-18 旧路径输出形态不变；`-Wall -Wextra` 零告警 |

验收口径：

- **P1 完成** → 库可声明支持 2024-11-05 ~ 2025-11-25
- **P2 完成** → 可声明支持 2026-07-28 核心
- **P3 完成** → 可声明 2026 授权模型完整

构建要求沿用：C23、libc-only 核心、`-Wall -Wextra` 零告警；每 P 独立 spec→plan→
实现循环，P1+P2 共享本设计文档的架构视图，执行计划按 P1→P2→P3 分期切片；
P3 因涉及 OAuth 流程重构，可拆为独立 spec。
