## §3 核心架构演进与规范落地核验

### 3.1 请求级单调 Arena 内存分配器 (`mcp_arena_t`)
- **文件**：`include/mcpkit/core/arena.h`、`src/core/arena.c`
- **特性**：
  - 8-byte/16-byte/任意 2 的幂对齐内存块分配，支持超大块透明动态扩容；
  - 栈顶 Realloc 原地伸缩（In-place bump）优化；
  - $O(1)$ 批量 reset 回收，块头链表保留复用，彻底规避高并发下 OS `malloc/free` 内存碎片；
  - 标准适配器 `mcp_arena_as_allocator`，无缝桥接标准 `mcp_allocator_t`。
- **与 Async Server 集成**：异步工作线程处理请求时全量使用 Arena 分配器，会话状态持久对象则由上游分配器承载，生命周期严格隔离。

### 3.2 直接流式 JSON-RPC 序列化器 (`mcp_json_stream_t`)
- **文件**：`include/mcpkit/protocol/json_stream.h`、`src/protocol/json_stream.c`
- **特性**：
  - 响应信封、错误信封及通知信封直接流式写入预分配内存；
  - 避免生成 AST DOM 树，消除 cJSON 对象节点分配与整树遍历释放开销；
  - 在保持 RFC 8259 严格 JSON 转义与数字精确输出的前提下，序列化性能大幅提升。

### 3.3 Streamable HTTP 环形事件缓冲区与断点续传
- **文件**：`include/mcpkit/transport/ring_buffer.h`、`src/transport/ring_buffer.c`
- **特性**：
  - 定长循环事件缓冲区，赋予每个 SSE 事件严格递增的单调 64-bit ID；
  - 客户端携带 `Last-Event-ID` 重连时自动线性回放缺失消息；
  - 缓冲区溢出驱逐老数据时感知最早存活 ID，超期重连精准返回 HTTP 410 Gone。

### 3.4 官方 MCP 2024-11-05 协议全能力矩阵覆盖
- **握手动态能力计算**：依据注册工具、资源与提示词自适应注入 `tools.listChanged`、`resources.subscribe` 等 capabilities；
- **提示词与参数规范**：官方 `mcp_prompt_argument_t` 声明与序列化；
- **动态资源模板**：RFC 6570 Level 4 模板匹配、路径变量提取与路由分发；
- **执行进度与取消令牌**：`mcp_tool_report_progress`、`mcp_cancellation_token_t` 与 `notifications/cancelled` 联动；
- **服务端反向 Ping**：对称双向 RPC 相关性与回调分发；
- **结构化日志广播**：`notifications/message` 多级别会话过滤广播。

## §5 性能微基准实测数据 (Microbenchmarks)

运行 `./build/benchmarks/bench_json_rpc` 100,000 次实测数据：

| 基准测试项 | 吞吐量 (QPS / Ops/sec) | P50 延迟 | P99 延迟 | 峰值内存 (RSS) |
|---|---|---|---|---|
| **Arena 分配 10 次与批量 Reset** | **29,426,642 ops/s** | 0.02 µs | 0.02 µs | 3.6 MB |
| **直接流式 JSON-RPC 序列化** | **15,242,027 ops/s** | 0.05 µs | 0.07 µs | 3.5 MB |
| **传统 JSON-RPC 消息解析 (DOM)** | **1,070,176 ops/s** | 0.80 µs | 0.87 µs | 2.8 MB |
| **传统 JSON-RPC 消息序列化 (DOM)** | **1,504,029 ops/s** | 0.63 µs | 0.76 µs | 2.8 MB |

- **结论**：直接流式序列化相比传统 DOM 树序列化带来 **10.13 倍** 的吞吐提升；Arena 内存分配/批量复位达到亚微秒极限性能（0.02 µs），消除了网络事件循环中的堆锁竞争。
